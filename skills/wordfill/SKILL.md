# Word 模板编译器（wordfill）

你的核心任务是**产出一份数据 JSON**：按字段填写配置和对话上下文，把每个字段的内容写出来。
把它交给内置引擎，就能套用 Word 模板生成正式文档。

## 核心原则：只管 JSON，不管模板

- **模板是黑盒**：Word 模板长什么样、什么排版、用什么字体、里面有哪些标记，都不是你的任务。
  **不要**去读模板的 XML、手工数标记、分析版式。模板的排版问题由用户负责。
- 你需要的只有**字段清单**（有哪些键）和**填写要求**（每个键填什么）。按这个顺序取：
  1. 用户已经给了 JSON 骨架 / 数据文件 → 直接看它，键名就是要填的字段；
  2. 用户给了字段填写配置 → 配置本身就是契约；
  3. 都没有、但给了 Word 模板 → 跑一次
     `python "<本 skill 目录>/scripts/wf.py" skeleton "<模板.docx>" -o "数据.json"`（自动扫描，不要手工分析）。
- **没有模板也要交付**。只要你产出了 JSON，任务就完成了一大半；生成文档是有模板时的最后一步。
- 回复里不要描述模板长什么样，也不要解释你"读懂了模板结构"——聚焦字段内容和依据。

## 工作流

1. **认契约**：读 JSON 骨架 / 字段配置，列出「字段 → 填写要求」。
2. **生成数据**：逐字段写值（规则见下），表格字段按行写。写成一份完整的 JSON 文件。
3. **校验**：`python scripts/wf.py check ...`（用法见下）。有 `[问题]` 先修数据。
4. **生成文档**（用户给了模板时）：
   `python scripts/wf.py fill "<模板.docx>" "数据.json" -o "<结果.docx>" [--pdf]`。
5. **交付**：以数据 JSON 为主交付物，附生成的 docx / PDF；说明每个字段的来源和仍需确认的点。

脚本依赖 `python-docx`：`pip install python-docx`。

## 字段内容怎么生成

步骤：

1. 读字段配置，把「字段 → 填写要求」过一遍；必填项、格式要求先标出来。
2. 通读对话、附件、代码，把可用素材按字段归类（哪个字段能用哪段信息）。
3. 逐字段写值，表格字段按行写；写完用 `wf.py check` 对齐字段清单。
4. 交付时说明每个字段的来源（上下文 / 附件 / 代码 / 推断 / 待确认），不用把全文贴进回复。

按优先级取用信息：

1. **用户的字段配置优先**：配置里写明填什么、从哪取、必填与否，就照着办，不要自由发挥。
2. **上下文里的现成信息直接搬**：对话中已出现的需求名称、表名、字段名、接口名、类名、改造点、SQL，原样写进 JSON，不要改写技术名词。
3. **描述性字段合理概括**：背景、目标、影响分析、测试要点这类字段，用上下文里的事实组织成工程文档口吻的书面语；不要口号和套话，不要编数字和结论。
4. **没有依据的事实类内容不许编**：表名、字段名、接口名、类名、SQL、版本号、日期、人名、金额、数量只能来自上下文、附件、代码库或用户确认。缺了就写 `【待确认：xxx】`，并在回复里说明还差什么。
5. **表格字段**：行数跟着真实内容走，不凑数、不留空行；配置要求的列每行都要有；同一列里连续重复的标识（表名、工程名）用 `合并列` 合并。
6. **多行文本**（SQL、代码、多条说明）在 JSON 字符串里用 `\n` 换行，程序会转成 Word 里的真换行。
7. **不适用的字段**给空值（`""`、`[]`），并在回复里说明"本次无数据库变更"这类前提，不要把占位符悄悄留在正式文档里。

循环字段（`{{#each 名称}}`）的每一项写在数组元素里，例如
`"风险": [ {"内容": "…", "应对": "…"} ]`，不要把循环里的字段放到顶层。

## 提问策略

先从上下文和附件里尽力补齐。只有**影响文档正确性**的信息缺失时才提问，一次最多 3 个问题；其余用【待确认】占位并继续产出，让用户先拿到可用初稿。不要为了问而问，也不要因为缺一个字段就停下整份数据。

## JSON 写法要点

完整规则见 [references/json-rules.md](references/json-rules.md)：格式修饰符、表格三种写法、循环、条件、图片、缺失数据行为。

- 键名必须和字段清单**完全一致**（含大小写、下划线、`客户.名称` 这种层级）。
- 表格字段的值必须是对象 `{"表头": …, "行": […]}` 或数组，不能是字符串。
- 日期字段给 `"2026-09-17"` 这种写法即可，显示格式由模板决定。
- 要给数据留注释就用下划线开头的键（`"_字段说明"`），程序会忽略，不影响生成。

## 校验与交付

```
# 有模板（最完整：能校验表格结构）
python scripts/wf.py check "<模板.docx>" "数据.json" [--config "字段配置.json"]

# 只有 JSON（用户没给模板，或你手上只有骨架文件）
python scripts/wf.py check --keys-from "骨架.json" "数据.json" [--config "字段配置.json"]
python scripts/wf.py check --config "字段配置.json" "数据.json"
```

检查项：缺键、空值（条件分支内的空值会被识别为正常并给提示）、表格值类型、表格行列与表头是否一致、配置里必填但为空、仍带【待确认】的字段。退出码非 0 就是还没通过。

交付前必须确认：

- `check` 通过；
- 有模板时，`fill` 的输出里没有残留 `{{ }}`（脚本会给出提示）；
- 表格行数、合并单元格、多行 SQL 与数据一致（有 PDF 时抽查那一页）。

## 命令

```
python scripts/wf.py skeleton "<模板.docx>" -o "数据.json"      # 模板没带 JSON 骨架时用它取字段清单
python scripts/wf.py check    "<模板.docx>" "数据.json" [--config "字段配置.json"]
python scripts/wf.py check    --keys-from "骨架.json" "数据.json"
python scripts/wf.py fill     "<模板.docx>" "数据.json" -o "结果.docx" [--pdf] [--blank]
python scripts/wf.py scan     "<模板.docx>"                     # 只想看字段名时
```

`scripts/` 指本 skill 目录下的相对路径，用绝对路径调用也可以。
