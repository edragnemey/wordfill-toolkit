# 数据 JSON 的写法规则

数据 JSON 的顶层必须是对象（`{ }`），键名对应 Word 模板里的标记名。
生成文档时程序只读取模板里出现的键；多余的键会被忽略并提示。

## 1. 键名

| 模板里的标记 | JSON 里的键 |
| --- | --- |
| `{{prd_name}}` | `"prd_name"` |
| `{{客户.名称}}` | `"客户": { "名称": … }` |
| `{{表格:改造清单}}` | `"改造清单": { … }` |
| `{{@公章}}` | `"公章": "图片路径.png"` |
| `{{$today}}` | 不需要出现在数据里（自动填） |

键名区分大小写、必须完全一致。不一致的标记在文档里会**原样保留** `{{...}}`。

## 2. 值怎么写

| 内容 | 写法 |
| --- | --- |
| 普通文字 | `"需求名称": "商户信息管理优化需求"` |
| 数字 | `"金额": 128600`（要显示成 128,600.00 就在模板里加 `{{金额\|千分位}}`） |
| 是/否 | `"需要停机": true` |
| 日期 | `"日期": "2026-09-17"`；模板写 `{{日期\|yyyy年M月d日}}` 就显示成 2026年9月17日 |
| 多行文本（SQL、代码、多条说明） | 字符串里用 `\n`：`"ALTER TABLE t\n    ADD COLUMN c int;"` |
| 列表（循环用） | `"风险": [ { "内容": "…" }, { "内容": "…" } ]` |
| 图片 | `"公章": "图片.png"` 或 `{"路径": "图片.png", "宽度": "4cm"}` |
| 给数据留注释 | 用下划线开头的键，如 `"_字段说明": {...}`，程序忽略 |

JSON 里不能直接敲回车换行，也不能把字符串拆成几段拼接；多行只能用 `\n`。

## 3. 模板上的格式修饰符（写在 Word 里，不在 JSON 里）

| 标记 | 数据 | 效果 |
| --- | --- | --- |
| `{{金额}}` | `128600` | 128600 |
| `{{金额\|千分位}}` | `128600` | 128,600 |
| `{{金额\|0.00}}` | `128600` | 128600.00 |
| `{{金额\|#,##0.00}}` | `128600` | 128,600.00 |
| `{{金额\|人民币大写}}` | `128600` | 壹拾贰万捌仟陆佰元整 |
| `{{日期\|yyyy年M月d日}}` | `"2026-09-17"` | 2026年9月17日 |
| `{{日期\|yyyy-MM-dd HH:mm}}` | `"2026-09-17 09:30"` | 2026-09-17 09:30 |
| `{{备注\|默认:无}}` | 缺这个键 | 无 |

## 4. 表格字段（`{{表格:名称}}`）—— 行数、列数都能变

模板里只写一行标记，整张表由数据生成。三种写法：

```json
"改造清单": [                                  // ① 最简：表头自动取第一条记录的键名
  { "工程": "dceppay", "模块或类": "SmartMerchantController",
    "改造说明": "新增商户进件外围入口。", "类型": "新增" }
]
```

```json
"改造清单": {                                  // ② 完整：指定列顺序、列宽、格式、合并
  "表头":   { "工程": "2.6cm", "模块或类": "4.6cm", "改造说明": "6.6cm", "类型": "1.6cm" },
  "列格式": { "金额": "千分位", "日期": "yyyy年M月d日" },
  "合并列": ["工程"],
  "字号": 9.5,
  "行": [ { "工程": "dceppay", "模块或类": "…", "改造说明": "…", "类型": "新增" } ]
}
```

```json
"明细": [ ["A", 1], ["B", 2] ]                 // ③ 二维数组，配合模板里的 {{表格:明细|无表头}}
```

规则：

- `行` 里每条记录**键名要一致**，缺的列会显示为空；多出来的键会被忽略并提示。
- 表头写成对象时，键的顺序就是列顺序，值是列宽（`4cm`、`30mm`、`1.5英寸`）。
- 同一列里**连续相同**的内容用 `合并列` 纵向合并，适合表名、工程名这类重复标识。
- 字号不写时按列数自动取 10.5 / 9.5 / 8.5 磅；列很多时建议显式给 `"字号": 9`。
- 生成的表格自动带浅灰边框、表头灰底加粗、数字列右对齐、跨页重复表头。
- 表格的值**不能是字符串**：`"改造清单": ""` 会被当作缺数据。

## 5. 循环字段（模板里用 `{{#each 名称}} … {{/each}}`）

模板里已经画好表头或固定段落时用循环，行数随数组长度增减：

```json
"员工": [ { "姓名": "李四", "职位": "工程师" }, { "姓名": "王五", "职位": "测试" } ]
```

- 循环里可以用 `{{_index}}` 取序号（从 1 开始）。
- 循环里没写到的字段会向上层数据里找，例如循环外定义的 `{{部门}}` 在循环里也能用。
- 数组为空 → 那一段/那一行自动消失。

## 6. 条件字段（模板里用 `{{#if 名称}} … {{/if}}`）

值可以是布尔、数字、字符串或对象；`0`、`""`、`false`、`[]`、`{}` 视为假。

```json
"需要停机": false,
"环境": "生产"
```

模板里可以写 `{{#if 需要停机}}…{{else}}…{{/if}}`、
`{{#if 环境 == 生产}}…{{/if}}`、`{{#if 金额 > 1000}}…{{/if}}`、`{{#if !备注}}…{{/if}}`。

## 7. 图片字段（`{{@公章}}`）

```json
"公章": "示例公章.png",
"logo": { "路径": "assets/logo.png", "宽度": "3cm" }
```

路径可以是相对模板文件所在目录的相对路径，也可以是绝对路径；支持 PNG / JPG / GIF / BMP / TIFF，不支持 EMF、WMF。

## 8. 缺失数据时的行为

| 情况 | 结果 |
| --- | --- |
| JSON 里没有这个键 | 文档里**原样保留** `{{标记}}`（方便查缺），并在结果里列为 missing |
| 值是空字符串 `""` | 该处替换为空白 |
| 模板写了 `\|默认:xxx` | 用默认值 |
| 生成时加 `--blank` | 所有没数据的标记替换为空 |

交付前如果结果里有 missing / 残留 `{{ }}`，视为未完成。
