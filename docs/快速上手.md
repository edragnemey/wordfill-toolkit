## 1. 下载与安装依赖

1. [下载源码 ZIP](https://github.com/edragnemey/wordfill-toolkit/archive/refs/heads/main.zip)，解压后进入有 `README.md` 和 `requirements.txt` 的项目根目录。
2. 安装 Python 3.10 或以上版本。Windows 安装时勾选加入 PATH；图形界面需要 Tkinter。
3. 在项目根目录打开终端，运行：

```bash
python -m pip install -r requirements.txt
```

macOS / Linux 如果使用 `python3`，请将命令中的 `python` 替换为 `python3`。生成 DOCX 不需要 LibreOffice，导出 PDF 才需要。

## 2. 先生成两份示例结果

在项目根目录运行：

```bash
python "工具-Word模板编译器/示例/智能办公空间/生成演示.py"
```

结果位于 `output/智能办公空间/`：

- `轻量版交付方案.docx`：3 行设备、3 列验收表、远程支持。
- `旗舰版交付方案.docx`：6 行设备、4 列验收表、驻场支持。

也可以按视频使用图形界面：

1. Windows 双击 `工具-Word模板编译器/一键启动.bat`；跨平台命令为 `python "工具-Word模板编译器/start_tool.py"`。
2. 选择示例目录中的 `交付方案模板.docx`。
3. 选择 `轻量版数据.json`，点击“查看/编辑”核对内容。
4. 指定输出文件名，点击“开始生成文档”。
5. 换成 `旗舰版数据.json`，使用另一个输出文件名，再生成一次。
6. 打开结果，检查字段、表格、图片、金额和分页。

金额小计、合计由数据提供，引擎负责格式化。修改数量、单价时请同步核对小计及预算。

## 3. 制作自己的 Skill

1. 为避免生成文件混入示例，将模板、系统示意图与 `字段说明.json` 复制到项目根目录的 `local/智能办公空间/`。
2. Windows 双击项目根目录的 `启动填写界面.bat`。跨平台命令为：

```bash
python skills/json-skill-builder/scripts/skill_builder_gui.py
```

3. 点击“从 Word 模板生成骨架”，选择复制后的模板。生成器会扫描 `{{字段}}` 并读取同目录的配套字段说明。
4. 核对每个字段的规则：信息从哪里取、采用什么格式、缺失时如何处理。例如“项目名称从用户需求提取；没有提供时先询问，不编造”。
5. 动态表格标记本身没有列定义。将验收清单的“列1、列2”改为“模块、验收项目”，再添加“通过标准、验证方式”，为每一列写清要求。也可按实际项目使用不同列。
6. 填写英文小写 Skill 名称，如 `office-delivery-demo`，确认配套 Word 模板和 ZIP 保存位置。
7. 先点击“检查有没有漏填”，再点击“生成 skill”。生成的 Skill 内部骨架会采用最终的列规则；原始扫描骨架可能仍保留占位列名。

选择 Word 模板会打包模板本身，**不会自动收集模板数据所引用的外部图片**。图片需要额外复制，详见下文。

## 安装并调用 Skill

本仓库生成器默认输出到用户目录下的 `.codex/skills/`。这与客户端识别 Skill 的位置是两回事。

当前 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)列出的 Codex 用户级目录是 `~/.agents/skills/`，项目级目录是 `.agents/skills/`。请把完整 Skill 文件夹复制到客户端识别的目录，保留 `SKILL.md`、`assets/`、`scripts/`、`references/` 等内容。未显示时重启客户端；其他客户端以各自说明为准。

在 Codex CLI / IDE 中可用 `$office-delivery-demo` 显式指定；其他界面通过对应的 Skill 选择入口调用。准备好需求、确认过的数据及图片，例如：

```text
$office-delivery-demo
请根据我提供的旗舰版数据生成办公空间交付方案。
使用配套模板和我提供的系统示意图，确认图片路径可读取。
不编造数量、日期和金额；缺失信息先列出来，确认后再生成 JSON 和 Word。
生成前执行数据校验，并说明哪些内容需要人工核对。
```

Skill 需要支持它的 AI 客户端来读取并执行；它不是独立的 AI 模型。仅使用现有 JSON 生成 Word，无需 AI 账号；AI 客户端与模型服务的费用由对应服务决定。

## 常见问题

### 两个启动入口有什么区别？

- 工具目录的“一键启动”：用模板和 JSON 生成 Word。
- 根目录的“启动填写界面”：编写字段规则，生成专属 Skill。

### 图片找不到怎么办？

相对图片路径默认以 **Word 模板所在目录**为基准。例如数据写 `"系统图": "系统示意图.png"`，请把这张图放在 Word 模板旁边。JSON 移动到其他目录不会改变这个基准。

生成 Skill 后，模板在 Skill 的 `assets/` 中；可把图片也放在 `assets/`，或者在 JSON 里使用实际图片的绝对路径。Windows JSON 路径建议使用正斜杠，如 `C:/项目资料/系统示意图.png`；如果使用反斜杠，需要写成 `C:\\项目资料\\系统示意图.png`。

开发者直接调用引擎时可显式设置 `base_dir`；本页说明的是默认行为。

### 双击没有反应，或提示没有 Python / docx / tkinter？

先在终端运行 `python --version`，确认版本与 PATH；再执行安装依赖命令。可用 `python -m tkinter` 检查 Tk 是否可用。若缺少 Tk，安装与当前 Python 匹配的 Tk 支持。用上方命令行入口启动，可以保留并查看错误提示。

### 模板没有字段，或结果仍有花括号？

模板需要事先包含 `{{项目.名称}}` 等标记。检查 JSON 键名和层级是否匹配，是否缺少必填数据。详细语法见[模板编译器说明](../工具-Word模板编译器/README.md)。

### 为什么轻量版显示有缺数据？

示例轻量版未提供驻场说明和备注：前者位于未启用的条件章节，后者使用模板默认值。界面的字段扫描提示需要结合模板判断；自己的必填内容仍需补全，并核对生成结果。

### 复制到另一台电脑就能运行吗？

复制完整 Skill 及其外部资源，并准备 Python 3.10+、python-docx 和支持 Skill 的客户端。可在 Skill 目录运行 `python scripts/env_check.py` 检查环境。需要 PDF 时再安装 LibreOffice。

### 怎样反馈问题？

[提交 Issue](https://github.com/edragnemey/wordfill-toolkit/issues/new?template=bug_report.md)，附上系统、Python 版本、复现步骤和报错。需要提供模板与 JSON 时，请先换成虚构数据。
